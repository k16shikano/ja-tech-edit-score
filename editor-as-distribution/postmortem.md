# editor-as-distribution: 技術レポートと再設計

**対象**: `editor-as-distribution` 系列（Phase 0–3 完了、Phase 4 未着手）
**結論**: 主仮説は C において支持されなかった。ただし方針そのものの棄却ではない。学習対象の粒度を誤った。

---

## 1. 結論

「編集者の推敲であるような条件付き分布を学習する」という方針は、順序を学習する方針より筋がよい。この判断は維持してよい。

失敗したのは実装ではなく、**学習対象の定義**である。文書対 $(x, y)$ に対する系列全体の対数尤度を最大化すると、勾配の大半は「どれだけ書き換えるか」という量的な成分に吸われ、「**この箇所に手を入れるべきか**」という判断の成分がほとんど残らない。

得られたモデルは、編集者の**文体**を捉えたが**方針**を捉えなかった。そして推敲技能の本体は方針の側にある。

数字で言えば、C（60 件、難しい境界）において

| 予測器 | 一致率 |
|---|---|
| 表層規則（編集距離大 / expand / 長い方、いずれも同値） | 32/56 = 0.571 |
| **$s_\mathrm{den}$（本系列）** | **33/56 = 0.589** [0.459, 0.708] |
| `pref-d-gpm-modernbert`（既存の順序モデル） | 33/56 = 0.589 |

表層を 1 件しか上回らない。区間は完全に重なる。

## 2. 技術的診断

### 2.1 $s_\mathrm{den}$ が実際に学習したもの

$s_\mathrm{den}(x,y) = \log p_\theta(y|x) - \log p_0(y|x)$ が C で何を選んでいるか。

| 傾向 | $s_\mathrm{den}$ が選ぶ側 |
|---|---|
| 編集距離が大きい方 | 41/56 = 73% |
| expand（Δ文字数が大きい方） | 34/56 = 61% |
| 注記なし | 46/56 = 82%（コーパス 97% なのでほぼ自明） |

一方、コーパス典型性との一致は低い。

| 比較 | 一致 |
|---|---|
| $s_\mathrm{den}$ vs joint 典型性（3 軸セルの相対頻度） | 13/42 = 0.310 |
| joint 典型性 vs 人手 | 17/42 = 0.405 |

**「コーパス表層典型性の復元」という仮説は棄却される。** A の 1716 件は shrink 920 / expand 738 で中央値 $\Delta = -2$、つまり最頻は縮小方向だが、$s_\mathrm{den}$ は 61% で expand を選ぶ。方向は典型と逆である。

残るのは**変更量の大きさ**への選好である。編集距離 73% がそれで、そして C の床がまさに編集距離規則の 32/56 だった。三つの表層規則（編集距離・Δ文字数・候補長）は 28 件で選ぶ側が異なるのに、一致率はいずれも 32/56 で同一である。**表層量はどれを使っても同じ天井に当たる。$s_\mathrm{den}$ もそこにいる。**

### 2.2 なぜそうなったか — 対数尤度の分散配分

$\log p(y|x) = \sum_t \log p(y_t \mid y_{<t}, x)$ の総和のうち、

- **大部分**は下書きからの写しに近いトークンで、どんなモデルでも高い尤度を与える
- **一部**は編集者の文体（語彙選択、句読点、語尾）で、適応が捉えやすく、量的にまとまっている
- **ごく一部**が「この箇所に介入するか否か」という判断に対応する

MLE はこの総和を最大化するので、**分散の大きい成分に引かれる**。1716 件・LoRA r=16 という規模では、周辺的な文体統計は学習できても、条件付きの判断構造までは届かない。

証拠が三つある。

**(a) ablation。** B valid で $\log p_\theta$ 単独 10/47 = 0.213、$\log p_0$ 単独 8/47 = 0.170、差が 44/47 = 0.936。両成分が単独では偶然を大きく下回るのに差だけが効く。これは尤度比が**局外母数を相殺した**ことの証拠だが、相殺後に残ったものが判断ではなく変更量だった。

**(b) C の誤り 3 件の中身。** 高 margin で人手と食い違った 3 件は、いずれも**介入の是非**の誤りである。

| 節 | $s_\mathrm{den}$ | 人 | 判断の内容 |
|---|---|---|---|
| picoruby | adapter（圧縮） | gold | Raspberry Pi と Pico の混同を防ぐ注記が要る |
| websocket | adapter（付録参照化・詳述追加） | gold | OS 別のループバック名は章内に残すべき |
| typetheory | gold（hedging・括弧説明を追加） | adapter | ここは最小修正でよい |

**足しすぎ側にも足らなさ側にも外れている。** 一貫しているのは「その箇所に何が必要か」を見ていないことである。

**(c) B と D 自己生成が高かったこと。** B valid 0.936、D 自己生成 0.970。どちらも対抗候補が別分布（Composer）ないし無選別の 1 サンプルで、**変更量だけで分離できる易しい境界**だった。C の対抗は暫定評価器が 8 本から選抜した 1 本で、そこでのみ 0.589 に落ちる。

### 2.3 関門 G2

D の 4 値順序ラベルに対する累積リンクモデル。

| 予測器 | RPS |
|---|---|
| 一様（各 0.25） | 0.232 |
| 周辺分布（train 比率） | 0.228 |
| **G2** | **0.226–0.229** |
| 表層特徴床 | 0.181 |

**G2 は周辺分布予測器と同水準である。** $(x,y)$ から確率分布としての情報をほとんど学習していない。学習曲線は 40 drafts で平坦（RPS 0.175 / 0.204 / 0.171 / 0.174）で、**データ量は律速ではない**。D の追加アノテーションは投資先として誤りである。

ただし D のラベル自体は健全だった。単変量 AUC は `delta_chars` 0.489、`char_ratio` 0.510 と偶然水準で、**D のラベルは文字数で決まっていない**。床 0.181 を支えているのは `edit_distance_norm` 0.642 と `punct_density_diff` 0.602 である。

すなわち G2 の失敗もまた、表層特徴を禁じた状態で LLM の隠れ状態から判断構造を取り出そうとして取り出せなかった、という同じ形をしている。

### 2.4 H3 は支持された

| 入力 | ラベル a 再現率 |
|---|---|
| $s_\mathrm{den}$ 単独 | 0.424 |
| $s_\mathrm{den}$ を除く | 0.703 |
| 全入力 | 0.703 |

$s_\mathrm{den}$ は負の推敲の検出に寄与せず、G2 は密度なしで同じ性能を出す。**密度と水準は別の情報である。** 設計解説 §5.6 の主張（密度は距離を測るが方向を持たない）は正しかった。

ただしこれは分解の正しさの確認であって、分解した先の各部品が C で効くことを意味しない。

### 2.5 評価設計の失敗

これが本系列で最も重い問題である。

**床の設定を三度誤った。**

1. B valid の対判別の床に、D valid の 4 値精度 0.613 を指定した（タスクも偶然水準も異なる）
2. `floor.py` の RPS が事例ごとの累積ではなく全体比率の累積を比較しており、0.001 という値を出していた
3. **C の床を一度も定義しなかった。** 0.589 を偶然水準 0.5 とだけ比べ続けた。実際の床は 0.571 である

**天井は測定不能のままである。** 再判定ファイルは合計 22 行あるが、`5_gold_vs_adapter_selected` に該当する `item_id` は 2 件のみ。2/2 = 1.000 [0.342, 1.000] では何も言えない。

**検証集合の大半が判別能力を持っていなかった。**

| 集合 | 名目件数 | 実際の判別的内容 |
|---|---|---|
| B | 378 | **4 件**（`pref_train` 328 件は「劣化していない Composer 生成は人間より下」という前提のエンコードで人手判定ではない。`pref_valid` 47 件のうち人手が Composer を選んだのが 4 件） |
| D 自己生成 | 200 | 人手判定なし。警告としてしか使えない |
| C | 60 | 56（唯一の難しい境界） |

**床 0.571、天井未測定、標本 56。この条件では、どんな手法を作っても有意差を検出できない。** 仮に当人の再判定自己一致率が 0.65 なら、床との差は 0.08 であり、56 件での検出は不可能である。

## 3. 生き残った知見

失敗の中で、次の設計に持ち越す価値があるもの。

### 3.1 密度と順序は別の情報を持っている

C 56 件での `ead-den-a-excl` と `pref-d-gpm-modernbert` の内訳。

| | 件数 |
|---|---|
| 両方正解 | 24 |
| 密度のみ正解 | 9 |
| 順序のみ正解 | 9 |
| 両方外れ | 14 |

**和集合で 42/56 = 0.75。** 同着 0.589 は同じ正解集合の偶然一致ではない。9 件ずつという対称的な内訳は、二つが別の成分を捉えていることを示す。

plan.md は「順序か分布か」という排他的な問いを立てたが、**その立て方自体が誤っていた**。到達可能かは別として、0.75 という数字は組み合わせに意味があることを示唆する。

### 3.2 D のラベルは健全

BRIEF.md の「文字数の違いだけを見て良し悪しを判断している傾向」は既存の `pref-*` 系列の症状であって、D のアノテーション自体は文字数に引きずられていない（`delta_chars` AUC 0.489）。D を作った工程は信頼してよい。

### 3.3 ペアを作らない学習は交絡を避けられる

$s_\mathrm{den}$ の学習は人間の推敲のみを使い、負例を用いない。したがって「正例群と負例群の生成過程の違い」という交絡経路が存在しない。この性質は維持すべきである。C での失敗は交絡ではなく、学習信号の粒度に起因する。

### 3.4 欠陥関門は機能する

G1 は規則のみで、人間推敲の通過率 0.991、運用分布（`adapter_samples`）で 11.5% を棄却する。安価で、実際に発火する。ただし劣化検出器ではない（D ラベル a の棄却は 11/267 = 0.041）。捕まえているのは no_edit と粗い欠落である。

### 3.5 margin は確信度ではなく原稿の性質を含む

$|s_\mathrm{sum}(\mathrm{gold}) - s_\mathrm{sum}(\mathrm{adapter})|$ の分散分解で、プロジェクト間 54.6% / プロジェクト内 45.4%。**margin の半分以上は「どの原稿か」で説明される。**

ただし C の符号判定は同一下書き内の対比較なので、この分散に汚染されない。汚染されるのは「margin の大小で分けた 0.679 と 0.500」の解釈のほうである。

実運用（1 下書きに対する 8 本の順位づけ）は原稿内で完結するので、8 本のスコア分布で正規化すれば原稿間の尺度差は自動的に消える。**C の対設計では得られなかった正規化子が、実タスクには存在する。**

## 4. 再設計

### 4.1 対象の再定義 — 方針と文体を分離する

診断 2.1–2.2 から、推敲を二段に分ける。

| 段 | 学習対象 | 現状 |
|---|---|---|
| **方針** $\pi(\text{介入するか} \mid x, \text{位置})$ | この箇所に手を入れるか、どの程度か | **未学習。C の誤りはすべてここ** |
| **文体** $p(\text{書き換え} \mid x, \text{位置}, \text{介入する})$ | 介入すると決めた後、どう書くか | $s_\mathrm{den}$ が捉えたのはここ |

この分解は Faigley & Witte 型の編集類型とは異なる。「冗長性の削除」「表記の統一」のような**解釈を要する型**を人手で定義するのではなく、「編集者はここに手を入れたか」という**観測可能な二値**だけを使う。編集者本人が区分していないものを区分しない、という制約は保たれる。

> **なぜこの分解が診断と整合するか**: C の 3 件（注記が要る / 章内に残すべき / 最小修正でよい）はすべて方針の誤りである。文体の誤りではない。adapter の文章は日本語として問題なく、編集者の語法からも外れていない。外れているのは**介入の判断**である。

### 4.2 学習データの形式

現行は文書対 1 件につき学習例 1 件である。方針の学習には、**1 文書から多数の判断点**を取り出す必要がある。

#### (a) 無編集の決定を教師信号にする

人間の推敲文書には、**編集者が手を入れなかった箇所**が必ず含まれる。これは現在ただの写しトークンとして尤度に寄与しているだけだが、実際には「ここは現状でよい」という**決定**である。

下書きを文ないし段落の系列 $x_1, \dots, x_n$ に分け、各 $x_i$ について「編集者はここを変更したか」を二値ラベルとする。A1（段落内推敲 1597 件）ではアラインメントが安定するので、この抽出は機械的にできる。

この形式の利点:

- **判断点が 1〜2 桁増える。** 1597 文書 × 平均 10 文なら約 16,000 の決定点
- **交絡が構成的に統制される。** 正例（編集された箇所）と負例（されなかった箇所）が**同一文書・同一編集者・同一話題**から来る。生成過程の違いという交絡経路が存在しない
- **変更量に引かれない。** ラベルは介入の有無であり、量ではない

#### (b) A2（段落またぎ 379 件）の扱い

アラインメントが定義できないので、(a) は適用できない。代わりに**ブロック単位の粗い決定**を使う。

推敲文のブロックが、下書きのどのブロック群から来たかを bag-of-token の重なりで対応づける（位置アラインメントを要しない）。各下書きブロックについて、保持 / 統合 / 削除 / 分割 の 4 値。これは型の分類ではなく、**構造的な操作の観測**である。

#### (c) 自己生成候補による方針の対比

方針の学習には「編集者がそうしなかった選択肢」が要る。これを外部モデル（Composer、汎用 LLM）から取ると、B と D で起きた交絡が再現する。

**同じ SFT アダプタから生成する。** 各下書きに対して $k$ 本サンプルし、人間の推敲と対比する。対抗候補が**評価時と同じ分布**から来るため、C の境界を学習時に再現できる。現行の `adapter_samples.jsonl` 480 件は、1716 件 × 8 本 = 13,728 件まで拡張できる（生成のみ、人手不要）。

> **これは B の設計の裏返しである。** B は「劣化していない別分布の推敲」を負例に置いたが、実際に必要だったのは「同分布のサンプルのうち編集者が選ばなかったもの」だった。

### 4.3 学習方法

#### 損失の集中

系列全体の MLE をやめ、**判断点に損失を集中する**。

最小の変更として、トークン単位の重み付けがある。下書きに出現しないトークン（bag-of-token novelty、位置アラインメント不要）を上げ、写しトークンを下げる。これだけで勾配の配分が変わる。$\alpha$ を 0.1 程度から探索。

より本質的には、4.2 (a) の二値決定に対する分類損失を主損失とし、系列尤度を補助損失にする。

#### 対比の入れ方

自己生成候補 $y^{(1)}, \dots, y^{(k)}$ と人間の推敲 $y^\ast$ に対し、**同一下書き内での対比**を取る。集合内正規化（softmax over $k+1$ 候補）にすれば、3.5 で述べた原稿間の尺度差が構成的に消える。これは実運用の best-of-8 と同じ形である。

$p_\theta$ の学習自体は人間の推敲のみの MLE を保ち（3.3 の性質を維持）、対比は**評価器側**に置く、という分離も選択肢になる。

#### 評価指標

方針段は二値分類なので、AUC と PR-AUC。文体段は現行どおり。**両段を単一スカラーに融合しない。**

### 4.4 メモリ — セクション・チャプター単位の学習

24GB 単体で長い系列を扱う際、**ボトルネックは重みではなく logits** である。

語彙 151k、系列長 $L$、bf16 で logits は $151{,}000 \times L \times 2$ バイト。$L = 32{,}000$ なら **9.7GB**、勾配を含めて 19.4GB。これだけで破綻する。

| 対策 | 効果 |
|---|---|
| **fused linear + cross-entropy**（cut-cross-entropy, Liger Kernel 等） | logits を一度も materialize しない。上記 19.4GB が実質ゼロになる。**最優先** |
| 4bit 量子化 + LoRA | 4B モデルで重み約 2.5GB |
| gradient checkpointing | 活性化が $L \times d \times \text{layers} \times 2$ バイト。4B・32k で約 5.9GB |

この三つで、**4B モデル・16k トークンは余裕、32k は逼迫しつつ可能**という水準になる。多くのセクションはこれで収まる。

チャプター単位（それ以上）には、追加の手段が要る。

**(a) 切り詰めた逆伝播（truncated BPTT）。** 系列をチャンクに分け、チャンク間で KV を detach して運ぶ。**前向きの条件づけは全長に及び、勾配はチャンク内に留まる**。長距離の勾配は失われるが、長距離の文脈は保たれる。単一 GPU での長文脈 LoRA 学習としては最も実際的である。

**(b) 二層表現。** 遠い文脈を要約ないし見出し列で表し、近い文脈を全文で与える。4.2 (b) のブロック単位の決定と相性がよい。macro 構造の判断に全文が要るとは限らない。

**(c) より小さいモデル。** 1.7B なら 32k が容易に載る。本系列の診断からすると、必要なのは流暢性ではなく構造の把握であり、**小さいモデルで長い文脈を見るほうが、大きいモデルで短く切るより有利な可能性がある**。この比較は実測する価値がある。

### 4.5 評価設計を先に作る

**次の系列では、学習を始める前に評価集合を確定する。** 本系列の最大の失敗はここにある。

必要なものは次の三つで、いずれも学習前に決まる。

1. **床。** そのデータセット上の表層規則と定数予測器。タスクごとに定義し、他のデータセットの数値を流用しない
2. **天井。** 当人が同一ペアを二度判定したときの自己一致率。分母 40 件以上
3. **判別的内容の件数。** 人手判定が割れている件数。これが 20 件を切る集合は検証に使わない

**人手作業の投資先は、D の追加アノテーションではなく、この評価集合である。** D の学習曲線は 40 drafts で平坦であり、追加しても効かない（2.3）。一方、天井が未測定であるために 0.589 の意味が確定していない。

具体的には、**(human, adapter サンプル) のペア 40–60 件を、同一の当人が時間を空けて二度判定する**。これで天井と判別的内容が同時に得られる。既存の C 60 件を流用してよいが、その場合 C は検証集合として消費される。

## 5. 何を捨てるか

| 捨てるもの | 理由 |
|---|---|
| 文書対に対する系列全体 MLE を主目的関数とすること | 勾配が変更量に吸われる（2.2） |
| D の追加アノテーション | 学習曲線が 40 drafts で平坦（2.3） |
| B を検証集合として使うこと | 判別的内容が 4 件（2.5） |
| 「順序か分布か」という排他的な問いの立て方 | 和集合 42/56 が二つの相補性を示す（3.1） |
| $s_\mathrm{den}$ を単独の順位づけ信号とすること | C で表層規則を 1 件しか上回らない（1） |

| 維持するもの | 理由 |
|---|---|
| 条件付き分布を学習対象とする方針 | 順序モデルの全順序仮定・原点不定性の問題は実在する。方針は正しく、粒度が誤っていた |
| ペアを作らない学習 | 生成過程の交絡を構成的に避ける（3.3） |
| 関門と順位づけの分離 | H3 が支持された。密度は方向を持たない（2.4） |
