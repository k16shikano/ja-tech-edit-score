# コミットと公開の注意

`docs-old/` の各文書に分散していた注意点のうち、いまも有効なものをここに集約する（2026-08-03）。

## 前提

このリポジトリのリモートは公開 GitHub（`github.com/k16shikano/ja-tech-edit-score`）である。
一方、学習データ・生成結果・判定ログは非公開原稿由来である。
コミットの判断は常にこの前提で行う。

## コミットしてよいもの

- スクリプト、Makefile、Dockerfile、ドキュメント
- データのスキーマ・テンプレート（`data/*.schema.json`、`data/*.template.jsonl`）。**テンプレートの例文は完全な架空文にする**。原稿の段落を「例」として貼らない（`hard_eval.template.jsonl` で一度やってしまった失敗）
- 同梱を決めた学習済みモデルの重みと指標（現状は `outputs/pref-static/` の `model.joblib` と `metrics.json` のみ）

## コミットしてはならないもの

- 原稿本文を含むデータ一式: `data/` 配下の学習データ・採掘結果・レビューキュー・退避（`archive-*`）・生成結果・判定ログ
- 執筆規範 `data/tech-writing-norms.md`（原稿由来の実例を含む）と、採掘対象の実リポジトリ一覧 `data/section_mining_manifest.json`（書籍リポジトリのパス・ブランチ構成が分かる）
- `outputs/` 配下の学習成果物（同梱を決めたもの以外）

なお、一度 push したものはコミットから外しても Git 履歴と GitHub 上に残る。
履歴からの完全削除が必要な場合は、`git filter-repo` などでの書き換えと force push が別途要る（実施は都度判断する）。

`.gitignore` はこの規則を既定で強制する形にしてある。
`data/` と `outputs/` は既定で無視され、公開してよいものだけを `!` で許可している。
新しく公開したいファイルができたときは、原稿の本文が含まれないことを確認したうえで `.gitignore` に許可を追記する。

## 成果物に本文を残さない

コミット対象かどうかに関わらず、学習・評価の成果物は本文を含まない形で作る。

- 学習メタ（`train_meta.json` など）は件数・ハイパーパラメタのみとする
- 活性・埋め込みの保存は id と形状のみとし、ペアテキストを残さない
- 外部 GPU ジョブの成果物には `project_id` や原稿のファイルパスを残さない
- 公開前の点検として、原稿に出現する 20 文字以上の連続部分文字列が公開対象に含まれないことを確認する

## Docker イメージ

- 学習・評価用イメージに原稿由来データを同梱する場合、push 先は非公開レジストリのみとする。公開レジストリは不可
- 外部ジョブでコンテナが破棄される場合、恒久成果物はアーティファクト経由の統計量・重みに限る
