## 評価器

目標は BRIEF のとおり。書き換えが、学習した人間の推敲に近いほど高い点を返す。
返したくないのは、下書きが人間の推敲より上、生成による書き換えが人間の推敲より上、である。
下書きと生成の上下はどうでもよい。

### 教師データ B（実施済み）

作り方は [DATA.md](DATA.md)。学習 328 件、検証は A2 の取り分け 50 件である。

### これまでに試した評価器

損失・点の計算・検証件数は BRIEF の各節。

文列型の Bradley-Terry は、検証 50 件で下書きを人間より上に置かず、Composer を人間より上に置く件が数件残った。
三点を一度に渡す評価器と、下書きと候補を一方ずつ渡す評価器は、人間を最上に置けず、下書きにも負ける件が増えた。

三点を一度に渡すと、人間の点を出す計算に、並んでいる他の候補の本文が入る。
一方ずつ渡しても、出力は一本の点であり、「未編集」と「近傍の別推敲」が同じ軸に乗る。

目標は文章の良し悪しではなく、その人がしたであろう推敲への近さなので、InfoNCE を学んだ。検証件数は BRIEF の pref-nce-section。

人間の推敲を 1、下書きと Composer を 0 とする検出も、文列型の点の上で学んだ。検証件数は BRIEF の pref-detect-section。
その検出に、Composer の点が下書きより高くなる項を足した学習は BRIEF の pref-detect-cd-section。

### スカラー仮説の検査

BRIEF のとおり、一本のスカラーで表せること自体を、A1 のあと B、および A1 と B の同時学習より先または並行して調べる。
手順は [DATA.md](DATA.md) の「スカラー仮説の検査」。

### 独立した人手判定

検証 50 件で人間の推敲を最上に置けた評価器について、学習に使っていない下書きでも同じかを人が見る。

下書き 40 件は `make freeze-8d-items` で固定済みである（`data/blind_eval/8d_items.jsonl`、手順は `data/blind_eval/8d_protocol.json`）。
出典は A1 の検証側。B の学習 328 件と検証 50 件に使った item は除く。
候補は、同じ指示文で Composer が温度 0.7、top_p 0.9、学習の乱数 `--seed` 1 と 2 で出す 2 本である。
評価器が選んだ候補は使わない。
判定は左右の役割を見せず、下書きと二案を並べて人が付ける。
集計の分母は、人が同等としなかった件。分子は、人の上下とその評価器の点の上下が一致した件数である。

ここを通るまで、評価器を DPO の教師や Best-of-N の裁定に使わない。

## 生成器

ペア単位の分割、Qwen3-8B への LoRA の SFT、検証側からの生成、人手のブラインド判定（BRIEF の評価用データ C）は実施済みである。
adapter は `outputs/Qwen__Qwen3-8B-pairsplit-v2/`。生成は `outputs/edit-sft-eval-v3/`。集計は RESULTS.md。

このあとの一手は、破壊率・無編集率・改善率の組み合わせで決める。中身は RESULTS.md。
DPO や Best-of-N は、評価器の独立した人手判定のあとである。
